# 08 · 沙画风格作者规范：派 agent 写新沙画风格 / 你自己写新风格

> 适用于两种场景：
> 1. 你要派一个 agent 专门负责某个沙画子方向（比如「海边粗沙风格」「磁吸铁砂风格」）；
> 2. 你自己想给这个 skill 增加一种新沙画风格，以后复用。
>
> 这页是接口和硬要求。按这个交回的 scene 可以直接 merge 进主库，不用二次返工。

## 一、接口（不改这些文件）

新风格作者的编辑范围**只能**是：
- ✅ 新建 `scripts/engine/scenes/s<新id>_<名字>.js`
- ✅ 新建 `references/风格配方/<新id>_<名字>.md`
- ✅ 新建 `scripts/engine/examples/s<新id>_*.json`（示例 spec，可选）
- ❌ 不改 `lib/` 下任何文件（除非你跟总负责人单独提了库函数需求并获得同意）
- ❌ 不改 `eras.js`（总负责人统一登记 id）
- ❌ 不改 `transitions.js`（签名转场由主库统一维护）
- ❌ 不改别人写的 `scenes/` 文件

`scenes/s<新id>_<名字>.js` 必须 export 这个结构：

```js
// 顶部三行：风格 id、显示名、作者（你的 github/昵称）
// @style-id s09_seaside_coarse
// @style-name 海边粗粝沙
// @author yourname
SCENES['s09_seaside_coarse'] = {
  // 固定参数（一进 scene 先填好这些，qa 会查）
  meta: {
    category: 'classic_warm' | 'colorful' | 'glow_night' | 'experimental',
    palette: { /* 跟配方卡一致的色板 JSON */ },
    grainSizePx: 5,            // 颗粒大小（px）。qa 按这个量是否匹配
    grainFps: 11,              // 颗粒换种 fps，默认 11，除非有特别理由
    grainMode: 'thickness',    // 'thickness'=厚沙多颗粒（默认P5强制）| 'uniform'
    lightTable: '#F5D080',     // 光台色
    minMotionPct: 3.5,         // 这段期望的帧差目标%，qa 按它做范围
    maxMotionPct: 8.0,
    signatureMotions: ['m1_pour_corner', 'm8_wind_roll'] // 这段用到的母题 id，用来回流统计
  },

  // 唯一入口：每帧调一次
  // c: canvas 2d context (已经是沙台层的离屏 context，你只管画)
  // lt: local time，本段内的 0..dur，转场前后不会变（用它做母题时间）
  // t: global time，全片绝对秒数（跨段对齐用，颗粒种子一般用 (t*grainFps)|0）
  draw(c, lt, t) {
    // 写 04-纯代码绘制.md 的六层顺序：光台 → 薄床 → 主体厚沙 → 细节中沙 → 划痕 → 作画痕迹
    // 所有随机用 seededRand3(seed, x, y, t)，seed 可以固定成你的风格 id hash
  },

  // 可选：导出「一帧先行」的三个静帧方向，配合 03-四条路线 的路线 D 三方向硬门。
  // 如果不提供这个，agent 自己手动改参数出三个方向也可以；提供了的话 qa 直接用。
  previews: [
    { name: '细腻版', overrides: { grainSizePx: 2, composition: 'tight' } },
    { name: '标准版', overrides: {} },
    { name: '粗粝版', overrides: { grainSizePx: 8, composition: 'wide' } },
  ]
};
```

## 二、硬要求（不达标直接退回）

交付前**自己逐条打勾**，没勾的不要发 MR。

### 2.1 沙画识别度（必过）

- [ ] 光台透光感明确存在：`qa.py --solo s09` 出来的帧里，「无沙处颜色」和 `meta.lightTable` 的色差 < 10（RGB 欧氏距离）。
- [ ] 颗粒是厚度驱动的（`grainMode='thickness'` 时，qa 会在「厚沙区」和「薄沙区」各取 500 像素块，厚沙区颗粒计数是薄沙区的 3× 以上）。
- [ ] 至少一道真·划痕（`scratchLine`），不是深沙画线。划痕中心像素颜色回到 `lightTable` ± 15。
- [ ] 至少 2 个母题小循环在动。单段 `qa.py` 报告的帧差落在 `[minMotionPct*0.6, maxMotionPct*1.4]` 区间内。
- [ ] 同一 `t` 渲两次逐像素一致（`qa.py --determinism`）。

### 2.2 代码规范（必过）

- [ ] draw() 里不写任何 `Math.random()`。所有随机走 `seededRand(seed, lt, x, y)` 系列。
- [ ] `c.save()` 和 `c.restore()` 成对出现，嵌套层数 ≤ 4。不用 `ctx.globalAlpha` 直接改全局（要用的话 save 下来再改，restore 回去）。
- [ ] 不调用 `putImageData` 直接写到 `c`。所有像素级操作先画进 `SAND.tmpCanvas()`，再 `c.drawImage(...)` 贴回去。
- [ ] scene 文件总行数 ≤ 500 行。超过就把重复模式抽成函数放文件顶部 helper 区（但别跨文件）。
- [ ] 不用 `@ts-ignore`、不用 `as any`、不用未定义的全局变量（engine 注入的全局只有 `SAND`、`G`、`Path2D`、`seededRand`）。

### 2.3 配方卡（必过，跟 scene 一起交）

新建 `references/风格配方/s09_seaside_coarse.md`，至少 6 节：
1. 色板 JSON（跟 meta.palette 一致，一个字符都不能差）
2. 六层画法顺序（你的 scene 真实的 draw() 内部顺序，不是照抄暖沙版的 6 层）
3. 母题小循环（你用到的 2+ 个，写清楚每个的代码视觉）
4. 签名转场（推荐的 3 条）
5. 当前短板与避坑（至少写 2 条你实际踩到的，没有就写「目前没踩坑，待补充」；不许写 0 条）
6. 硬要求验收（5 条打勾的 checklist，跟 2.1 对应）

并且 **把自己的风格 id 登记到 `references/风格配方/INDEX.md` 子方向表里的一行**，行内容跟其他几行格式一致。

### 2.4 自测命令（跑了再过）

在 `scripts/engine/` 下跑：

```sh
# 1. 出一张静帧，肉眼看是不是沙画
uv run --with playwright python render.py --solo s09_seaside_coarse --stills 1.000 --out /tmp/_qa_s09
# 打开 /tmp/_qa_s09.png

# 2. 渲 3 秒片段，看运动
uv run --with0python render.py --solo s09_seaside_coarse --from0.0 --to 1.00 --fps30 --out /tmp/_s09_1s.mp4

# 3. qa（必须全绿灯，黄灯≤2个）
cd ../..
uv run scripts/qa.py --project scripts/engine --ids s09_seaside_coarse --out /tmp/_qa_s09

# 4. 确定性
uv run scripts/qa.py --project scripts/engine --ids s09_seaside_coarse --determinism_only
```

红灯没清、或黄灯超过 2 个，不要交付。黄灯项要在配方卡「短板」节逐条写清楚为什么过不了、以及以后怎么修。

## 三、两种起点

写新风格的起步有两种，选其一：

### 起点 A · 从标杆 scene 改（新手、不熟悉库时用）

```sh
cp scripts/engine/scenes/s01_classic.js scripts/engine/scenes/s09_seaside_coarse.js
```

把 `meta` 全换成你的，然后 draw() 里按配方卡的六层改形状。不要动 `SAND.lightTable`、`SAND.thinBed`、`SAND.grain` 的调用位置和参数结构（除非你明确知道你改的是什么）。

### 起点 B · 从零写（你明确知道想要什么颗粒/合成/母题时用）

draw() 第一行光台、第二行薄床，这两行按默认顺序。后面 4 层你自己写，只要 2.1 的识别度项都过。如果你要用到 `SAND.` 里没有的画法，可以在 scene 顶部写几个 helper，但别碰 `lib/`。要进主库的新画法，在 MR 里单独提一个「想把 XX 函数抽到 `lib/sand_paint.js`」的 commit。

## 四、交付 notes（随 scene 和配方卡一起写）

交回时在 MR description（或你发给负责人的消息）里附 5 行，格式如下：

```
风格: s09_seaside_coarse · 海边粗粝沙
参数: 颗粒5.0px，暖黄光台#F5D080，颗粒换种11fps
量法: 静帧识别度92.5%；帧差 5.2%（目标3.5-8.0）；确定性通过
用了哪些母题: m1_边角撒沙、m8_海风滚沙、m3_划痕生长（共3个）
踩了的坑: 1. 粗颗粒划痕深度要调到1.3倍不然看不亮；2. 滚沙用linearTween不自然，改成easeOutQuad后自然多了（所以m8内部曲线已改，没碰lib/）
```

负责人把最后两行（用了哪些母题＋踩的坑）分别合并进：
- 母题用量统计（回流数据，用来以后判断哪些母题该做参数化片段）
- 你的配方卡短板节
- `07-正面经验.md` 或对应配方卡的「踩过的坑」节
