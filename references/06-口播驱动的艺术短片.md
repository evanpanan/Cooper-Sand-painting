# 06 · 口播驱动的沙画短片：把一篇文稿变成一支沙画片

> 适用于「用我的口播做一段沙画动画」。口播 + 沙画是天然组合：声音在讲故事，沙画在用手画故事的画。

## 一、输入物（你得先有这三样，缺一样都不要开始写代码）

1. **口播文稿 `.txt`**：按自然段落分行，不要一句话一行。行前不要序号、不要时间戳。
2. **口播录音 `.wav`**：48kHz、单声道（配音员录好的），或者用 `scripts/koubo.py` 生成配音（读 `13-口播与语音复刻.md`）。
3. **沙画风格锁定**：三大类（暖沙/彩沙/荧光沙）选其一，色板按 `色板.md` 锁定。

如果文稿还没写，先写**口播稿**再写镜头表，不要反过来。沙画的镜头节奏是被口播速度拖着走的，不是自由设计的。

## 二、第一步：出时间轴（文稿逐句标时）

先跑强制对齐：
```sh
uv run scripts/analyze/align_script.py --audio 口播.wav --script 文稿.txt --out 时间轴/
# 产物：
#   时间轴/逐句对齐.json   每一行文稿 + 它的 start/end 时间戳(秒) + 置信度
#   时间轴/波形.png         全稿波形图 + 每句的时间框，肉眼看有没有对齐错
#   时间轴/强制对齐报错.txt 置信度<0.7 的句子，人工复核
```

置信度 <0.7 的句子一定要人耳听一遍重标时间，不然后面所有镜头表全错。

把对齐后的 json 变成一张 5 列的表（存成 `镜头表素材.md`）：
```
句 1 (0.00s–1.42s):「大家好，我是 Cooper」
    关键名词: Cooper, 我
    动词: 是, 打招呼
    → 建议画面: 沙台上慢慢画出 Cooper 的头像（或手的剪影，见角色精细度），从左到右慢慢成形，落字在 1.40s 那拍
```

动词是动作锚点：「说」「开始」「变成」「结束」这些词出现时，画面上**应该有沙画动作刚好发生**（撒沙起、划痕终点、抹平开始）。不要等一句话说完了才开始画。

## 三、第二步：写镜头表（照 `镜头表模板.md`）

沙画口播片的镜头表有几个特殊规则（跟普通艺术动画不同）：

1. **一句话 = 0.8–1.5 个镜头**。不要一句话切 4 个镜头，观众听声音跟不上画面；也不要 5 句话一个镜头，观众会睡着。一句话对应 1 个镜头是默认；特别长的句子（>4s）才拆成 2 个。
2. **每镜的「物」必须来自那句话的关键名词**。那句话讲「花朵」，镜里就画花；不要那句话讲「花朵」你画星空（转场可以，主体不行）。
3. **屏上字 ≤ 那句话的核心词**。比如口播说「2024 年我们做了三件事」，屏上字写「2024 · 3 件事」，不要把整句话贴上。字要用**沙画的划痕字法**：先堆厚沙铺底，然后用 `scratchLine` 把字的笔画「划」出来——亮线笔画就是字。
4. **开头 3 秒（第一句话前或第一句话前半）必须是沙画开场**：光台亮 → 撒沙 → 第一幅画。不要上来就直接有一幅完成的画。
5. **相邻两镜用沙画签名转场**（撒/抹/流/散），不要硬切。硬切＝「几张沙画 PPT」，签名转场＝「沙画师在台上连续作画」。
6. **最后一句话说完后留 3–5 秒的完整沙画＋慢呼吸光台**。让观众看最后一眼、吸收信息，不要口播一结束就黑场。

口播驱动片**不需要过「脉冲节奏窄桥」**（停住→快推→停住）。沙画口播片的节奏来自「跟着口播一起画画」，不是解说视频的脉冲推镜头。镜头如果要动，用**慢推**（10 秒推 15%，匀速），配合口播情绪推近，不要有突然的砸入和快推。

## 四、第三步：过 lint（有口播版）

```sh
uv run scripts/storyboard_lint.py <项目>/镜头表.md --script 文稿.txt --align 时间轴/逐句对齐.json
```

多了两个检查（没有口播版的 lint 不查这俩）：
- **屏上数字 = 口播里说的数字**。口播说「三件事」屏上不能写「5 件事」；口播说「3 亿」屏上不能写「3,0000,0000」（格式也得一致）。红灯要改。
- **镜头时长和对应句子时长差 < 0.5 秒**。画面切到下一镜了但那句话还没说完，或者那句话说完了 0.8 秒才切下一镜，都会有割裂感。红灯要改镜头表的时间段。

红灯没清不许开始写代码。

## 五、第四步：出画面轨

两种路径，选其一：

**路径 A · 纯 scenes（推荐，质量最高）**：每镜写一个 `scenes/镜NN.js`，把 eras.js 段落表的时间对齐到口播的时间轴。转场用沙画签名转场。整段模式一次出片。
```sh
# eras.js 里每段的 start/end 要和 时间轴/逐句对齐.json 完全对齐
# （可以直接 import 那个 json）
uv run --with playwright python 代码工程/render.py --out 画面轨.mp4 --fps 30
```

**路径 B · 参数化片段（速度快）**：每镜一个 `镜NN.json` spec，选对应的沙画语法（`09-沙画动画语法.md`）。沙画语法的片段是 JSON 驱动的，不用写 JS。单个片段最多 8 秒，超了拆镜。
```sh
for i in 01 02 03 ...; do
  uv run --with playwright python 代码工程/render.py --spec 镜$i.json --out 渲染/镜$i.mp4
done
# ffmpeg concat，顺序和镜头表一致
```

路径 A 的成片流畅度明显高（因为转场是沙画签名转场）。路径 B 适合第一次做、预算时间 < 半天的短口播片。

## 六、第五步：混音 + 合成

```sh
# 画面轨已经是 mp4（没有音道），口播是 wav，配乐（可选）是 wav
# 三轨混音：口播主、配乐次、声效（sfx）最轻
ffmpeg -i 画面轨.mp4 \
  -i 口播.wav \
  -i 配乐.wav \
  -filter_complex "[1:a]volume=1.0[a1]; [2:a]volume=0.25[a2]; [a1][a2]amix=inputs=2:duration=shortest[aout]" \
  -map 0:v -map "[aout]" \
  -c:v copy -c:a aac -b:a 192k \
  成片_口播版.mp4
```

如果在 `render.py` 里已经写了 sfx 表，画面轨里已经带了 sfx 声道（`--sfx_only` 可单独导出），那上面的混音改成 amix=inputs=3 即可。

## 七、踩过的坑

- **口播说太快，沙画还没画完就下一句了**。要么让配音员重录那几句放慢，要么把那几句的画面改成「先铺好画，再慢慢划亮线」（亮线划比撒沙成画快 2 倍）。不要强行用快进式撒沙，会很假。
- **画面和口播词的「关键词对不上」**。比如口播说「那年冬天特别冷」，画面却是一朵夏天的花。观众潜意识会不舒服，但说不出为什么。对齐方式：每镜的主物＝那句话的主名词（第三步表写了就要照做）。
- **屏上字和口播不同步**。口播已经说到下一个词了，屏上字还停在上一句。把字的出现时间写在 `eras.js` 每段的 `text_at_t` 字段里：`text_at_t: 0.3` 表示进入该段 0.3 秒后字才亮（用划痕字法，亮线划完 = 字显完 = 刚好口播说到那个词）。
- **最后一镜停太短**。口播一结束就黑场，观众连最后一眼都没看到。强制：最后一段的 eighths 数要比对齐时间长 3–5 秒，eras.js 最后一段的 `pad_end = 5`（引擎会自动多停 5 秒才输出黑场）。
- **配乐音量太大盖住口播**。混音时口播是绝对主角：口播 1.0，配乐 0.2–0.3，sfx 0.15。用耳朵听，不用眼睛看电平表。
