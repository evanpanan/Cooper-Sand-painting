# 13. 口播制作与语音复刻

> 本文档覆盖口播音频的三条生产路径：用户自备录音 → 系统 TTS 占位 → 音色复刻训练。每条路径从命令到最佳实践。配合 `references/口播API.md` 做参数速查。

---

## 0. 开工前：判断走哪条路径

| 路径 | 适用场景 | 质量上限 | 成本 | 谁做 |
|---|---|---|---|---|
| **A. 用户自带录音** | 用户有现成的 wav，或愿意去录音棚/手机录 | 真人最高 | 低（仅需对齐） | 用户录 + agent 对齐 |
| **B. 系统 TTS 合成** | 先出样片、节奏对齐、后期可替换真人声 | 占位可听 | 零成本（内置合成） | agent 全自动 |
| **C. 音色复刻训练** | 长篇系列内容，需要统一音色但用户不能每次录 | 接近真人 | 高（需素材 + 用户自训） | 用户准备素材 + 自己训 |

实际项目最常见的组合是：**B 出节奏版 → 用户按节奏录 → A 替换成片**。

---

## 路径 A：用户提供现有录音 WAV

### A.1 收文件时的硬要求

收到用户的 wav 先检查，不合要求就让用户重录或转格式：

```bash
ffprobe -v error -show_entries stream=sample_rate,channels,codec_name -of default=noprint_wrappers=1 用户录音.wav
```

期望输出：
```
codec_name=pcm_s16le        # 或 pcm_24le / pcm_32le，PCM 无损
sample_rate=48000           # 或 44100；48k 优先
channels=1                  # 单声道，解说必须单声道
```

不符合 → 用 ffmpeg 转：
```bash
ffmpeg -y -i 用户原始.m4a \
  -ar 48000 -ac 1 -c:a pcm_s16le \
  口播_已转.wav
```

### A.2 把文稿拆成句（对齐前置条件）

文稿 `<项目>/文稿.txt` 每句一行。如果用户给的是整段文字，先断句：

```
文稿.txt：
第一句，关于主题是什么。
第二句，核心观点和数据。
第三句，例子或故事。
第四句，总结和下一步。
```

每行不要超过 30 个字，超过的在逗号/句号处拆。

### A.3 逐句对齐

用外部对齐工具产出 `逐句对齐.json`（结构见 `口播API.md`）。如果没有对齐工具，用手工锚定法：

```bash
# 先把全片 wav 按静音切句
ffmpeg -i 口播_已转.wav -af silencedetect=noise=-30dB:d=0.4 -f null - 2> sil.log
# 从 sil.log 提取 silence_start / silence_end，把每句裁成单独文件
```

然后对 `逐句对齐.json` 里的每句：
- `sentence` = 文稿中对应一行
- `start` / `end` = 该句在整片 wav 里的秒（保留 3 位小数）
- `confidence` = 手工对齐填 0.8，工具对齐填工具给出的值

### A.4 koubo.py 调用方式

```bash
# 先告诉 capabilities 我们走 existing 模式
python3 scripts/capabilities.py voice enable --mode existing --recording-dir <项目>/录音

# 列出可用录音（会把目录下所有 wav 列出来）
python3 scripts/koubo.py voices

# 取某一句合成（其实是按文件名匹配；找不到就提示你加 --file）
python3 scripts/koubo.py say "第二句，核心观点和数据" --out 片段_02.wav
# 或直接指定文件
python3 scripts/koubo.py say "" --file <项目>/录音/句02.wav --out 片段_02.wav
```

## 路径 B：系统 TTS 合成（内置数学合成）

### B.1 启用 synth 模式

```bash
python3 scripts/capabilities.py voice enable --mode synth
```

### B.2 按文稿逐句合成

文稿 `文稿.txt` 每行一句：

```bash
# 逐句循环合成
i=1
while IFS= read -r line; do
  [ -z "$line" ] && continue
  printf -v pad "%02d" $i
  python3 scripts/koubo.py say "$line" \
    --voice default_narrator \
    --out <项目>/音频/句${pad}.wav
  i=$((i+1))
done < <项目>/文稿.txt
```

`koubo.py say` 在 synth 模式下的行为：
- 用 numpy 做共振峰合成，a/e/i/o/u 五个元音分别对应不同的基频 + 共振峰
- 中文按字符处理：遇到 aoeiuv 拼音元音（文本中出现的英文字母）用合成音；其他字符用短静音占位
- 实际听感是 "呜呜嗯嗯" 的占位音，**不是中文语音**，但节奏长度可用
- 输出 22050Hz 单声道 PCM WAV，时长稳定可复现

### B.3 合成整串拼接

```bash
# 写 concat 文件
for f in <项目>/音频/句*.wav; do printf "file '%s'\n" "$f"; done > <项目>/音频/句列表.txt
# 拼起来 + 句子间插 0.25 秒静音
ffmpeg -y -f concat -safe 0 -i <项目>/音频/句列表.txt \
  -af "adelay=250|250:all=1" \
  -ar 48000 -ac 1 -c:a pcm_s16le \
  <项目>/音频/口播_合成版.wav
```

### B.4 估算语速（调动画节奏用）

synth 模式下，一个中文字符大约占 0.18 秒（含 0.06 秒字间静音）。你可以用它在写镜头表阶段估算每句时长，不必等合成。

验证：
```bash
python3 scripts/koubo.py say "这是一句测试用的中文句子" --out /tmp/test.wav
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 /tmp/test.wav
# 输出 ≈ 0.18 * 13 ≈ 2.34 秒
```

## 路径 C：音色复刻训练（私有流程）

> **法律与合规提醒**：音色复刻必须遵守你所在地区的相关法规。仅对**用户本人的声音**、且用户**书面或明确口头同意**的情况下进行素材收集和训练。不得用于未经授权的第三人声音克隆。

### C.1 koubo.py train — 只输出指引，不执行训练

```bash
python3 scripts/koubo.py train --help
```

实际执行：
```bash
python3 scripts/koubo.py train --out <用户自己的目录>/voice_training_assets
```

这条命令**不会读取、上传、处理任何音频**。它只做两件事：
1. 在 `--out` 下写一个 `素材清单.md`，列出用户需要准备的内容
2. 在 stdout 打印同样的清单，包括目录结构建议

### C.2 用户需要准备的素材（`koubo.py train` 输出的清单）

```
voice_training_assets/
├── 素材清单.md               ← koubo.py train 写出
├── recordings/               ← 用户自己放 wav
│   ├── clean_read_01.wav     ← 安静环境朗读，48kHz 单声道
│   ├── clean_read_02.wav
│   └── ...
├── transcript.csv            ← 用户自己填（或用 ASR 生成后校对）
│   # 格式：wav 文件名 | 文字稿（逐字）
│   # clean_read_01.wav,第一句原文……
│   # clean_read_02.wav,第二句原文……
└── consent.txt               ← 用户必须手写签字（或电子确认）：
                                "我确认以上音频出自我本人，
                                 同意用于沙画动画的个人音色复刻，
                                 不用于其他用途。签名：___ 日期：___"
```

素材数量要求（最低 → 推荐）：
- 最低可用：10 分钟干净朗读
- 质量可用：30 分钟（覆盖数字、常见词汇、不同情绪）
- 高质量：2 小时 + 情绪变化录音（平静、兴奋、严肃、温柔）

### C.3 训练本身不在此技能内执行

满足素材要求后，用户需要用**自己选择的训练方案**在自己的机器/云实例上执行训练。可能的选项：
- 开源 TTS 克隆框架（用户自选）
- 商用 API 提供的音色上传服务（由用户管理密钥）

训练产出的模型文件放在 `--voice-model-dir` 下，然后：

```bash
python3 scripts/capabilities.py voice enable \
  --mode trained \
  --voice-model-dir <用户模型目录> \
  --voice-name my_voice
```

之后 `koubo.py say --voice my_voice` 会优先使用用户训练好的模型；如果找不到实际的合成脚本，会自动降级到 synth 模式并打印警告：

```
[koubo] WARNING: trained 模式配置了但找不到外部合成脚本，降级使用 synth 占位音
```

**不会静默欺骗**：用户始终知道听到的是合成占位还是真实音色。

## 音频最佳实践（三条路径通用）

### 目标输出规格

最终成片混音用的口播轨：
| 参数 | 要求 | 原因 |
|---|---|---|
| 采样率 | 48 kHz | 视频标准 |
| 声道 | 1（mono 单声道） | 解说通常居中，单声道省体积且兼容好 |
| 编码 | PCM S16LE（wav） | 预混阶段无损 |
| 响度 | -2 dB LUFS 集成（±0.5） | 解说为主，要清晰；用 `ffmpeg -filter:a loudnorm=I=-2:LRA=3:TP=-1.5` |
| 开头静音 | 0.3 s | 给 ffmpeg 预卷，避免爆音 |
| 结尾静音 | 0.3 s | 不被硬切掉尾音 |

### 响度标准化命令

```bash
ffmpeg -y -i 原始.wav \
  -af "loudnorm=I=-2:TP=-1.5:LRA=3:linear=true,
       adelay=300|300:all=1,
       apad=pad_dur=0.3" \
  -ar 48000 -ac 1 -c:a pcm_s16le \
  口播_已标化.wav
```

### 混音比例（默认推荐值）

| 音轨 | 相对音量（ratio） | 说明 |
|---|---|---|
| 解说（narration） | **1.0** | 基准，永远最响 |
| BGM（背景音乐） | **0.2 – 0.3** | 只铺氛围，绝不能盖过解说 |
| SFX（撒沙、手指划沙等音效） | **0.15** | 点缀，偶尔突出 |

用 ffmpeg 混音（三路）：
```bash
ffmpeg -y \
  -i 视频无声.mp4 \
  -i 口播.wav \
  -i bgm.wav \
  -i sfx.wav \
  -filter_complex "
    [1:a]volume=1.0,apad[a_narr];
    [2:a]volume=0.25,aloop=loop=-1:size=2e+09[a_bgm];
    [3:a]volume=0.15[a_sfx];
    [a_narr][a_bgm][a_sfx]amix=inputs=3:duration=first:dropout_transition=0[a_out]
  " \
  -map 0:v -map "[a_out]" \
  -c:v copy -c:a aac -b:a 192k \
  -shortest \
  成片_带音轨.mp4
```

如果只有解说+BGM，把 `amix=inputs=3` 改成 `2`，并删除 `[3:a]` 那条。

### 质检：过一遍自己的耳朵

最终混音完之前：
1. 拉一遍整片，听**有没有某一句突然轻/响**（归一化会修大部分，但句间差异还在）
2. 找 5 秒纯 BGM 片段，再找 5 秒解说+BGM，对比——解说要比 BGM 明显清楚，不是"一样响"
3. 用笔记本电脑外放 + 手机外放各听一次（别只戴耳机，用户最终可能用手机看）
