# 12 · 口播整片与经验回流：从第一支沙画片到第二支、第三支

> 适用于：完整做过一支口播沙画片（镜头表→代码→成片→交付）以后，怎么把经验沉淀回 skill，让第 N 支越做越快、越做越好。
> 第一次做的人先读 06 号，读流程。本页是「做完了一次之后」的进阶。

## 一、口播整片的 6 个时间比例点（真实数据）

做过 3 支以上沙画口播片后，时间消耗基本稳定在这个分布：

| 阶段 | 占总工时 | 说明 |
|---|---|---|
| 1. 写镜头表（含口播对齐＋lint） | 15–20% | 别嫌慢，lint 省的返工时间比这个多 |
| 2. 路线 D 三方向静帧＋用户确认方向 | 5–8% | 第一次做一定要，不确认后面的返工率 60% |
| 3. 参数化片段 spec JSON 编写 | 25–30% | 占比最大。如果用 scenes 手写路线 A 占 40–50% |
| 4. 逐镜渲染＋中途修 bug | 20–25% | 渲染时间本身不长，主要是修 qa 红黄灯 |
| 5. 拼接 + 混音 + 最后一遍肉眼审 | 8–10% | 机械操作，别在这里省时间 |
| 6. 独立 agent 审片 → 修 → 交付 | 10–15% | 一定要独立审。自己审不出自己的惯性错误 |

如果你的实际占比和这个差太多（比如写镜头表只花了 5%），回去看那一阶段是不是跳步骤了。返工 80% 来自前三阶段跳步骤。

## 二、做完一支片的回流清单（每一支必须交）

交付完后，必须填以下 6 项进 skill（不用写长，每行一句也行）。不回流 = 下一支片回到起点。

### 回流 1 · 把本支片里「新增的沙画形状/母题」抽成新的函数

如果本支片的 scenes 里写了一段重复 3 次以上的代码（比如「画一棵沙画树」「画一个沙画饼图」），抽成：
- `SAND.drawTree(c, palette, cx, cy, size, t)` 放进 `lib/sand_paint.js` 新节。
- 在对应风格配方卡的「母题表」加一行。
- 在本文件 `新增母题` 节登记。

### 回流 2 · 本支片踩过的具体坑 → 写到对应 reference 的「踩过的坑」

- qa 红灯且不是代码 bug 是理解错了的 → 写到对应号的 reference。
- 被独立审片标红的具体帧号 + 为什么 → 写到对应 style 的配方卡「短板与避坑」节。
- 绝对不要写「这次颜色没调好」这种空话，要写「`scratchLine` 的 `depth` 参数给了 0.6 光台透不出来，调到 1.0 后划痕亮了 3 倍」的可操作描述。

### 回流 3 · 本支片「做对了且效果显著」的 → 写进 `07-正面经验.md`

照 `07-正面经验.md` 的格式：
- 做法（可操作的参数）
- 证据（哪支片哪段、量出来的数）
- 为什么（机制解释）
- 何时用/不用

没有数据的「我觉得挺好」不算，要可量化（审片通过的比例、qa 指标、观众识别耗时等）。

### 回流 4 · 新增的沙画语法变体 → 写进 `沙画语法/`

如果本支片基于 y1~y8 改了参数并做成了新的有效结构（比如 y7 加了堆积式柱状图的变体），在 `沙画语法/y7_xxx.md` 末尾「变体」节登记。或者作为新语法 y9 新建文件。

### 回流 5 · 口播对齐误差统计 → 写进自己的笔记（可选回流到 skill）

把本支片中「画面和声音」的最大偏差 t（秒）记录下来。连续做 3 支后你会得到一个稳定的常数偏移（比如 +0.08s）。以后所有 sfx 和动作点自动加这个偏移，不用每次人工调。

### 回流 6 · CHANGELOG.md 记一行

格式：
```
YYYY-MM-DD · 片名《Cooper创业之路》· 1920×1080@30 · 时长 4m32s
  - 新增: SAND.drawTree() / 沙画语法 y7_variant_stackbar / 配方 s10_金色庆典沙（实验性）
  - 沉淀: P11「划痕字笔画顺序按真实书写顺序」（正面经验）
  - 踩坑: scratchLine depth 默认 0.6 透光不够（配方 s01/s04 都已更新默认值到 1.0）
```

## 三、第二支片的提速方法（做完第一支后）

做完第一支后，你手里有了一支真实成片。第二支片开始，不要从空模板开始：

1. **开新项目时复制第一支的整个目录**，删掉代码工程的 scenes/镜*.js 保留骨架。
2. **第一支的风格色板/语法选择直接复用 70% 以上**。除非题材完全不搭，否则 theme 和 palette_name 不要换（一致性高、出片快）。
3. **第一支的 eras 段落结构复用**：如果两支都是「开场→3 段故事→结尾」，eighths 数的分布几乎可以照抄（只改每段文字内容）。
4. **新 scene 从相近 scene 改，不是空写**。比如第一支有一朵花的 scene，第二支要画一颗星，就把花的 scene 复制一份改形状参数，不要从零搭六层。

按这个方法，第 2 支比第 1 支省 35% 工时；第 3 支在第 2 支基础上又省 20%。第 4 支开始工时基本稳定在模板化程度上。

## 四、独立审片的标准流程（沉淀一次后一直用）

派独立 agent 审片的 prompt 不要每次重写。下面这段是沉淀过的、沙画片专用的审片 prompt：

```
你是沙画动画的审片人。没参与制作，只看成片，挑具体问题。
看片方法：全屏 100% 看两遍，第一遍全片不带暂停看整体，第二遍逐镜 0.3× 慢放抓细节。
只写你在成片上看到的具体问题，每个问题必须包含「分:秒 时间码 + 帧上具体现象 + 为什么是问题」。
不要写空泛话。不要写「整体挺好」「再优化一下」。

检查清单（看到才写，没看到不要写）：
1. 沙画识别度：[时间码] 这一帧有没有明显的颗粒？有没有光台透光感？划痕是不是亮线？
   - 如果像「黄色图片＋噪点滤镜」、像矢量图、像 PPT，标红。
2. 作画过程：[时间码] 这一段有没有真的看到沙在「撒/划/流/抹」？还是只有图片淡入淡出。
3. 颗粒闪烁：[时间码] 这一段有没有突然全屏颗粒位置跳变（跳变帧差 >10%）。正常 11fps 换颗粒应该是微微滚动感，不是闪。
4. 手掌抹除假不假：[时间码] 这个抹平转场有没有「被推出来的沙垄」？还是纯矩形擦除。
5. 字的清晰度：[时间码] 这一帧的字能不能在 0.5 秒内读完？读不完要么字太大要么字没按划痕字法做。
6. 转场对齐声音：[时间码] 这个转场中点和口播/音乐的拍点对齐了吗，还是差了半拍以上。
7. 最后一镜：结尾有没有完整画面停留 3 秒以上再淡出（不是立刻抹掉黑场）。
8. 蓝紫光台：如果不是荧光沙风格，有没有出现蓝/紫/青占主色的帧？
9. 口播同步：[时间码] 这句话的关键词（数字/名词），对应的画面动作是不是提前 0.1s 动手了（P7）。
10. 整屏一致性：有没有某一帧的颗粒大小/颜色/光台色和前后帧明显不搭，像从别的片插进来的。

写完后按严重度分三档：🔴红灯（必须改）/🟡黄灯（建议改）/🟢绿灯（做得好的地方，也鼓励标出来）。
最后汇总：红灯几个，黄灯几个，一句话的整体观感。
```

把审片结论放进 `<项目>/审片/*.md`（文件名：`审片_YYYYMMDD_独立agent.md`）。交付脚本 `deliver.py` 会自动读这个目录。

## 五、常见的「回流阻塞点」和疏通法

| 阻塞点 | 现象 | 疏通法 |
|---|---|---|
| 「这坑太小不值得写」 | 很多小坑没写，下支片踩同样的小坑。 | 强制规定：每支片至少写 2 条坑，不管多小。「scratchLine 第 4 个参数 width 传了数字不是对象被静默忽略」这种小坑写下来下次直接省 10 分钟。 |
| 「正面经验没有数据」 | 「我觉得颜色调对了」但没有对照。 | 做对的那一刻，立刻对比前后两张静帧导出放 `项目/qa/`，文件名带参数值。后面写正面经验直接引用。 |
| 「没有独立审片资源」 | 没审就交付，返工率高。 | 办法：做 A 片时审 B 片，用同一 agent 的不同会话。审片要求 agent 「只读成片不读制作过程」，所以审自己的另一支片的成品同样有效（只要你没让它读制作 notes）。 |
| 「抽函数怕抽错进 lib」 | 不敢改 `lib/sand_paint.js`，重复代码留在 scenes 里。 | 新函数先写在 scene 顶部 helper，第 2 支片又用到了再移进 lib。两阶段：scene 内重复 3 次 → 写进 lib。中间缓冲。 |
